# Video Remake Pipeline

将用户给出的视频链接或本地视频转成一套完整、可继续制作的复刻分镜包。默认主动执行，不把用户已经明确交代的工作拆成一连串确认问题。

## 1. 默认约定

除非用户另有说明，使用以下默认值：

- 抽帧间隔：每 2 秒一张，从 0 秒开始。
- 画幅：保持源视频画幅；接近 16:9 时统一按 16:9 输出。
- 分镜图片：每张抽帧对应生成一张。
- 视频镜头时长：默认 4 秒；建立场景和终章可用 5 秒；过渡镜头可用 3 秒。
- 输出语言：所有主提示词、负面提示词、说明和文件标题均使用中文。
- 人物动作：只缓慢走两三步，衣袖、衣摆和发丝轻微摆动。
- 环境动作：云雾、水流、树枝、光尘缓慢自然运动。
- 镜头动作：每镜只使用一种主要运动，限缓慢推近、拉远、横移、摇摄、轻微升降或小幅环绕。
- 不切镜：每张图片只生成一个连续镜头，不在单条提示词里切换机位。
- 命名：`shot-01_4秒_场景名.png`；编号两位数，场景名使用 4–10 个中文字符。

当视频超过 120 秒或预计超过 60 张抽帧时，先完成下载、探测和抽帧清单，向用户说明预计分镜数量与生成成本，再开始大批量生图。短视频直接执行完整流程。

## 2. 安全和来源边界

- 只处理用户提供或明确授权使用的视频。
- 公开链接可使用 `yt-dlp` 下载；不要绕过登录、验证码、付费墙、地区限制或 DRM。
- 链接需要授权、Cookie 或私有账号时，报告精确阻塞，并请用户直接上传视频或完成登录。
- 保留原始视频，不覆盖、不转写用户的源文件。
- 调用需要登录、积分或付费的外部生成服务前，说明服务与消耗；优先使用当前会话已经可用的内置图片生成工具。
- 不要宣称 Midjourney 或其他平台已经生成成功，除非当前会话确实存在可调用工具并返回成功结果。

## 3. 创建运行目录

在当前工作区创建唯一的运行目录，格式建议：

```text
<视频短名>-remake/
├── source/
├── frames/
├── generated/
├── manifest.json
├── contact-sheet.jpg
├── image-prompts-zh.md
├── video-prompts-storyboard-zh.md
├── 4k-finishing-guide-zh.md
└── README.md
```

从本 Skill 所在目录向上两级得到 `<PLUGIN_ROOT>`。优先调用随插件提供的脚本：

```bash
python3 <PLUGIN_ROOT>/scripts/prepare_video.py <URL或本地视频> \
  --output-dir <运行目录> \
  --interval 2
```

脚本负责：下载或复制源视频、用 `ffprobe` 探测信息、逐点抽帧、生成联系表和初始 `manifest.json`。如果依赖缺失，报告缺失项及安装需求，不要假装完成。

## 4. 检视与视觉反推

1. 先查看联系表，识别镜头数量、场景切换、统一风格和重复构图。
2. 再逐张查看原尺寸抽帧。不要仅凭缩略图判断人物大小、建筑纹理或字幕。
3. 在 `image-prompts-zh.md` 顶部先写一份统一视觉基准：
   - 世界观与时代；
   - 建筑语言与主要材质；
   - 主色、辅色和亮度；
   - 云雾、水体、植被等环境元素；
   - 镜头焦段、机位与景别；
   - 人物服饰、数量和大小比例；
   - 所有分镜统一禁止出现的元素。
4. 为每张抽帧写一条独立完整的中文图片生成提示词，不引用“同上”“继续上一张”等隐含上下文。
5. 忽略源视频中的字幕、水印和平台界面，不把它们写进生成画面。

### 图片提示词结构

每条提示词按以下顺序写成一个自然段：

1. 景别、机位和画面重心；
2. 环境、建筑及其空间关系；
3. 人物数量、位置、服装和比例；
4. 光线、色彩、空气透视和材质；
5. 摄影语言、画幅和清晰度；
6. 构图锁定与禁止项。

如果用户指定 Midjourney：只写一个连续的正文提示词，参数全部放在末尾；不要使用会被当前模型版本拒绝的多文本提示词或多个 `::` 段。版本参数可能变化，提交前核对用户当前界面或官方说明。

## 5. 巨物尺度与明亮仙境修正

当源片或用户目标属于仙宫、神殿、巨构、云海等史诗场景时，必须明确控制人物和建筑的比例，避免人物过大或小到不可读：

- 人物全身约占画面高度的 4%–8%，远景但轮廓与服装颜色清楚。
- 最近的主要建筑至少为人物高度的 8–15 倍；背景巨构可达人物高度的 30–80 倍。
- 建筑、悬崖、云海等环境承担至少约 75% 的视觉重量。
- 使用大全景或超大全景、深景深、明显空气透视和多层空间参照。
- 明确写出“人物只是尺度参照”“不要人物特写”“不要前景巨人”“人物不要蚂蚁大小”。

画面亮度使用高调仙境方案：珍珠白、象牙白、暖金、淡青蓝，高空晨光或柔和日照，金色体积光、发光云海、清透空气、丰富鎏金高光和干净阴影。避免灰暗曝光、脏黄、沉闷低饱和、黑压压的阴影和末日氛围。

如果源视频不是这种风格，不要强行套用仙宫方案；忠实分析源片自身的比例、亮度和美术方向。

## 6. 生成分镜图片

图片生成工具可用时，默认生成全部分镜，不只生成样片：

1. 每次使用对应抽帧作为唯一画面参考。
2. 一张抽帧对应一次生成，保持源构图和镜头方向。
3. 使用统一视觉基准约束所有镜头的材质、色彩与世界观。
4. 生成后逐张检查：建筑是否融化、栏杆是否弯曲、人物数量是否改变、人物是否突然变大、亮度是否变暗、服装颜色是否漂移。
5. 不合格镜头只重做该镜头，不重做已通过的图片。
6. 根据后续镜头时长和场景名重命名为 `shot-XX_时长_场景名.png`，保存到 `generated/`。
7. 将最终文件路径、场景名和视频时长写回 `manifest.json`。

图片生成工具不可用时，仍应交付完整 `image-prompts-zh.md`，并清楚标记“提示词已完成，图片尚未生成”。

## 7. 生成中文图生视频分镜提示词

创建 `video-prompts-storyboard-zh.md`。文档顶部包含通用设置和统一负面提示词；之后每个 Shot 依次包含：

- 标题：`Shot 01 · 4秒 · 场景名`
- 对应图片的绝对路径预览
- 时长
- 镜头运动
- 人物动作
- 一条可直接复制的中文主提示词

每条主提示词必须明确包含：

1. “将输入图像作为完全一致的首帧”；
2. 单镜头、连续、明确秒数；
3. 一种缓慢稳定的主要镜头运动；
4. 人物只走两三步，保持原数量、身份、服装颜色和画面比例；
5. 云雾、水流、倒影、衣袍或树枝的轻微自然运动；
6. 建筑几何结构、构图、亮度、色彩和画幅全程锁定；
7. 不切镜、不突然变焦、不出现剧烈动作。

通用中文负面提示词至少包含：

```text
快速镜头运动，突然变焦，快速甩镜，手持抖动，镜头晃动，切镜，延时摄影，人物特写，巨大的前景人物，增加人物，减少人物，重复人物，身体畸形，多余肢体，面部扭曲，建筑闪烁，建筑融化，栏杆扭曲，几何结构变化，纹理游移，光线不稳定，曝光闪烁，严重运动模糊，文字，字幕，水印，标志
```

没有独立负面提示词输入框的工具，将其改为“不要出现：……”后追加在主提示词末尾。

## 8. 4K 后期方案

创建 `4k-finishing-guide-zh.md`：

- 记录源视频和预计成片的分辨率、帧率与画幅。
- AI 放大首选 Topaz Video；慢镜头、复杂建筑和远景小人物优先测试 Proteus Natural，细节不足时再小范围测试 Rhea。
- 输出目标为 16:9 时使用 3840×2160；非 16:9 素材保持原比例，不擅自裁切。
- 保持源帧率；除非用户要求，不同时开启补帧、防抖和强锐化。
- 外部云服务上传前需要用户授权；登录、积分或付费步骤不能静默执行。
- 只有 `ffmpeg` 时，可以提供 Lanczos 技术放大，但必须标注它只是尺寸放大，不是 AI 细节重建。
- 提醒用户：AI 放大能改善观感，但不会把低清源素材变成真正原生拍摄的 4K。

如果用户已经提供了生成完成的小视频，按 Shot 顺序检查并给出逐镜 4K 设置；只有在本机工具和授权都具备时才实际执行放大。

## 9. 验证与交付

执行：

```bash
python3 <PLUGIN_ROOT>/scripts/validate_run.py <运行目录>
```

完成标准：

- 抽帧数量、图片提示词数量、生成图片数量和视频分镜数量一致；
- 每个 Shot 的编号、时长、场景名和文件名一致；
- Markdown 图片链接全部有效；
- 图片画幅一致，没有混入字幕、水印或黑边；
- 联系表已人工查看，人物尺度和亮度符合视觉基准；
- `README.md` 写明总镜头数、总建议时长、尚未完成的外部步骤和所有关键文件链接。

最终回复直接给出运行目录、联系表、图片提示词、视频分镜提示词和 4K 指南的可点击绝对路径，并简要报告镜头数量、总时长及任何真实阻塞。
